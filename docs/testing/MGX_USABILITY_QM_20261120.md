## 判定と確認環境

人が目的の操作に進めるか、文言を読まなくても次の操作を判断できるか、同じ内容や入口が重複していないかを確認した。画面操作で観察した事実と、その影響についての評価を下表に記録した。優先度は今回の操作観察にもとづく提案である。

対象は本番 `https://mgx-poker.com` と、公開コミット `45c7a36627be2d632884b426accb546b16a8bc10`。調査開始時の `main` と公開コミットは一致した。

| 項目 | 実施内容 |
|---|---|
| PC | macOS Safari。QA専用の別ウインドウで操作 |
| スマホ | Xcode Device HubでiPhone 17・iOS 26.5シミュレータを起動。Safari、縦向きで操作 |
| 認証 | 一時的なQA用アカウントでログイン。調査後にアカウントを削除し、旧セッションがAPIで401になることを確認した |
| 判断材料 | 実画面、操作後の表示、アクセシビリティツリー、対象コミットの実装 |
| QMの方法 | AIによる操作とヒューリスティック評価。新規利用者に操作してもらうユーザビリティテストは未実施 |
| 改善の状態 | 下表の24件は指摘の記録。修正後の再QMは未実施 |

## 重要な導線の再現

### U01 学習からのゲーム開始

1. 本番にログインする。
2. メニューの「種目を学ぶ・MIX練習」を開く。
3. 学習画面の「メニュー」で `/menu` に戻る。
4. 「ゲームを選択」で `/games?mode=cash` を開く。
5. Badugiの「このゲームで開始」を押す。
6. `/game?variant=badugi&aiTier=standard` で登録・ログインの入口が表示される。
7. その入口を押すと、ゲーム開始前のメニューが表示される。
8. そこからキャッシュゲームを再選択すると、同じURL内で卓へ入れる。

[7の画面](../../reports/usability-qm/2026-11-20/pc-selected-game-returned-menu.jpg)。実装でも、ルート側のゲーム選択はURLへ遷移し、Appの初期画面は特定のnavigation stateがなければtitleとなる。URLのvariantとaiTierを付けただけでは、この初期分岐でゲーム開始につながらない。[ゲーム選択](../../src/ui/screens/GameSelectorScreen.jsx#L425)、[App初期状態](../../src/ui/App.jsx#L469)

修正後は、この手順で追加の登録・メニュー選択を要求せず、選択したBadugi・Standardの卓へ入ることをPC・iPhoneで再確認する。ブラウザ更新からの復帰も確認する。
