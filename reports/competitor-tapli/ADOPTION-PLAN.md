# MGXに取り込むもの・磨いてから取り込むもの

2026-09-20。前回の[86項目比較](GAP-REGISTER.md)を、実際にプレイヤーが使う単位で17案にまとめ直した。今回は採用方針の整理であり、実装完了の記録ではない。

優先したいのは、**大会の条件が読めること、言語を迷わず変えられること、説明が短く自然で実際の動作に合っていること**。その上で、練習・復習・友人対戦を充実させる。競合の機能数を揃えるより、MGXのどの画面でも同じ感覚で使える状態を目指す。

## 採用を勧める9案

この区分は、取り込む価値が明確なもの。実装がすべて軽いという意味ではない。

| ID | 取り込むもの | MGXでの形 | 採用する理由 | 優先 |
|---|---|---|---|---|
| A01 | 分かりやすい言語設定 | 共通設定に「日本語 / English」。初回画面にも入口を置き、選択直後に全画面へ反映。再起動後も保持 | 設定の場所や入った経路で挙動が変わらないことが基本 | 最優先 |
| A02 | 短く自然な説明文 | ボタンは「何をするか」、補足は「条件・結果」。不要な宣伝、開発用語、将来予定を減らす | 読む負担を減らし、押した後の動作を予測できる | 最優先 |
| A03 | 種目をまたいだ操作の統一 | 丸卓、座席、手札、金額入力、交換/確定、履歴への入口を共通化。対人卓にも適用 | 2−7とNLHで別のアプリに見える問題を繰り返さない | 最優先 |
| A04 | 全公開種目の簡潔なルール説明 | 「勝ち方・使うカード・交換回数・ベット形式」を同じ順に表示。詳細は別に開く | 初めての種目でも何をすればよいか分かる | 高 |
| A05 | すぐ使える練習設定 | CPU速度、降りないCPU、同じ持ち点で再開を一か所に集める。練習条件を卓にも表示 | 設定の意味と結果が分かりやすく、反復しやすい | 高 |
| A06 | 登録前の体験プレイ | 公開種目を選んでCPUと1ハンド。保存したくなった時に登録へ案内 | 最初に操作感を確かめられる | 高 |
| A07 | 友人に渡せる招待と教材 | 招待URL/QR、MIX構成の共有、開始手札の練習リンク | 相手に説明する手間を減らせる | 高 |
| A08 | 結果から復習へ進む導線 | 「このハンドを見る」「メモを残す」「同じ手札で練習」。対応している操作だけ表示 | MGXの既存の再生・メモ・練習をつなげられる | 高 |
| A09 | 遊べる範囲が正確に伝わる表示 | 通常公開と試験公開を区別。参加できない理由と、今できる代替操作を示す | 「選べるのに遊べない」「説明と違う」を減らす | 最優先 |

A01はTapliの優位性として確定した項目ではなく、今回追加したMGX自身の改善案。Tapliのホーム設定を開いた範囲では言語切替を確認できなかった。A02も文章の作者がAIかどうかを判定するものではなく、読みやすさと具体性の評価。

## MGX向けに磨いてから採用する8案

| ID | 候補 | 参考になる点 | MGX向けに磨く部分 | 採用条件 |
|---|---|---|---|---|
| B01 | トーナメントのストラクチャー | レベル・休憩・強制ベットを確認/編集できること | 最初は短め/標準/じっくりから選び、持ち点・レベル時間・種目・休憩を先に見せる。詳細表と編集は次の画面 | 見た条件と実際の進行が一致。保存・再開でも変わらない |
| B02 | MIXプリセットとDC | 定番セットをすぐ選べ、切替方法も選べること | HORSE/8/10の構成を是正。次の種目と変わるルールを予告。選択者が決めるDCとランダムを別名にする | 全構成種目が遊べる。FL/NL/PLと切替時点を検証 |
| B03 | 自由入力の役判定 | 対局せずに勝敗や分割を確かめられること | カード入力を簡単にし、勝つ理由・採用カード・分配を図で示す。内部スコアや評価器名は通常表示から外す | 実対局の評価器と同じ結果。重複カード・ロー不成立・同点も説明できる |
| B04 | 全席を自分で操作する練習 | 複数の立場から考えられること | 手番の席を明示して切替。見せる手札の範囲と巻き戻しを整理。初心者には最初から全部見せない | 別の席のつもりで誤操作しない。対人の伏せ札処理と分離 |
| B05 | 多種目・多人数の友人戦 | MIXを実際に仲間と遊べること | 共通の卓UIと接続状態表示。まず他種目の2人戦、その後3〜6人へ | サーバー側で合法手・伏せ札・切断復帰・精算が成立 |
| B06 | リアル卓用のゲーム札・時計 | 店舗や練習会でも使えること | 遠目に見える種目/現在/次レベル。StudとFLの単位を明確化。縦は操作、横は大きな表示に適した配置 | 画面復帰しても時計がずれず、ゲーム内大会との違いが明確 |
| B07 | 手札に応じた種目提案・レビュー | 選ぶ理由や判断を学べること | 候補を少数に絞り「この手札はA-5ローを作りやすい」など具体的な理由を先に出す | 検証していない最適性やEVを断定しない。対象局面へ戻れる |
| B08 | 定期大会とシーズン | 同じ時間に集まって遊ぶ理由を作れること | 最初は小さな定期会と結果一覧。複雑なポイント消費や決勝枠は後から | 対人基盤と運営担当、実際の参加需要が揃う |

B01の競合根拠：[Tapliトーナメントタイマー](https://taplimix.app/tools/timer)。これはリアル卓用ツールであり、同じ自由編集をTapliのオンライン大会で使えると確認したものではない。B02：[プリセット](https://taplimix.app/presets)、B03：[役判定](https://taplimix.app/tools/qualifier)、B07：[種目提案](https://taplimix.app/tools/recommend)、B08：[シーズン](https://taplimix.app/season)。B05の部屋内仕様は前回の公式説明根拠で、実対人プレイは未確認。

## トーナメントのストラクチャーはこう磨く

**参加前に「どんな大会か」が分かる画面にする。** 現在のMGXには大会進行とブラインド表の基盤がある。新しく一から作る必要はないが、現行の大会選択は表の名前や英語ラベルが中心で、全体を読み取るには足りない。

| 場面 | 見せるもの・できること |
|---|---|
| 大会を選ぶ | 種目/MIX、参加人数、開始持ち点、進行の速さ、CPU大会か友人大会か。所要時間を出すなら実測に基づく目安 |
| 条件を確認する | 開始ブラインド、レベル時間、アンティ、休憩、再参加の可否、受付終了条件。無い機能は対応済みのように表示しない |
| 詳細表を見る | 現在と次のレベルを強調。全レベルも確認可能。NL/PLのSB・BBと、FLのSmall/Big Bet、StudのAnte/Bring-inを区別 |
| 自分で調整する | プリセットを複製して変更。最初は持ち点とレベル時間など主要項目、詳細編集は折りたたむ |
| MIXを設定する | 構成、順番、何ハンド/何周で変更するか。レベル上昇と種目変更は別々の条件として扱う |
| 保存・共有する | 名前を付けて保存。開始時の設定を履歴と再開データに固定し、あとでプリセットを編集しても進行中の大会は変わらない |
| プレイする | 残り時間、次の強制ベット、休憩までの時間、次種目。数値表を読まなくても分かる |

「15分で必ず終了」などは約束しない。CPU速度、人数、操作時間で実際の長さが変わる。アプリ内の短い練習大会と、店舗のリアル卓向けストラクチャーも別のプリセットとして扱う。

MGXにある `tournamentPresets.js` の短時間設定は定義の存在確認まで。現行大会選択画面がそのプリセットを採用済みとは数えない。現行経路は `tournamentStages.js` と `tournamentBlindSheets.js` を使う。

## 言語設定は「どこでも同じ」を完了条件にする

- 設定名は「言語 / Language」、選択肢は「日本語 / English」。国旗だけにはしない。
- メニュー、対局、大会、履歴、ルール、エラーを同じ言語設定に接続する。ゲームの固有名詞は表記を決めて統一する。
- 言語を変えても対局・入力中の金額・手札の選択・大会設定を失わない。
- 再読み込み、戻る操作、別画面への移動でも選択を保つ。
- 日本語だけでなく英語でもボタンの折返し・はみ出し・入力欄の圧迫を確認する。
- 日付や桁区切りを整え、エンジン内部の金額・カード表現とは分ける。

静的コード確認では、`RootApp.jsx` の `/menu` と `/dev/menu` は `MainMenuScreen` に言語と変更処理を渡していない。同画面の既定値は日本語、変更処理は何もしない関数。その経路では、言語選択が機能しない構造になっている。通常App側には言語保存・変更処理があるため、共通管理へ統合するのがよい。今回、画面操作による再現はまだ行っていない。

## 説明文を自然にする基準

「AI臭さ」は作者の判定には使わず、次の観点で直す。

1. 同じ説明を見出しと本文で繰り返さない。
2. 抽象的な宣伝より、何をできるか・何が起きるかを書く。
3. 設定は選択肢だけで伝わるなら説明を付けない。必要なら一文。
4. 専門用語は意味のある場面に限る。プレイヤー向けの言葉と開発用語を混ぜない。
5. エラーは、起きたことと次にできる操作を書く。
6. 「追加予定」「対応済み」などの状態は現在の動作と照合する。
7. 同じ操作には同じ言葉を使う。「開始」「参加」「再開」は使い分ける。
8. 日本語と英語は直訳で長さを揃えるより、それぞれ自然な短文にする。

以下は現行コードの表記に対する修正案。置換はまだ行っていない。

| 現行の表記・説明 | 修正案 | 意図 |
|---|---|---|
| ポーカープラットフォーム | MGX、または「ゲームを選ぶ」 | 抽象的な分類名を見出しにしない |
| 各ゲームの詳しいルールは今後この画面に追加予定です。 | 説明を削除し、既存のルール一覧を表示 | すでにある機能と矛盾させない |
| 詳細設定は今後追加予定です。現在はテーブル上のクイック設定を利用できます。言語はここで切り替えられます。 | 実際に変更できる設定項目だけを並べる | 長い前置きを不要にする |
| テーブルレイアウト、サウンド、HUD 情報、言語などを変更します。 | 現状に合わせて「表示言語を変更できます。」などへ | 未実装の設定まで約束しない。項目追加時に更新 |
| Global Rating Console | 自分の成績 | 現状が個人の記録であることを伝える |
| AI Tier | CPUの強さ | 利用者が選ぶ意味を伝える |
| Blind Sheet | ストラクチャー | 表の名前だけでなく「各レベルのブラインド」を開けるようにする |
| 地区代表を決める中規模 MTT。テンポも一段階速く、上位入賞で全国への切符を得ます。 | 地方大会。店舗大会で1回優勝すると参加できます。 | 現在の参加条件を具体的に伝える。進出条件は実装で確認して別表示 |

動的な文言も揃える。例：「保存に失敗しました。もう一度保存してください。」「あと2枚交換できます。」「次はRazzです。Aは最も低いカードとして扱います。」いずれも該当する状態だけで出す。長い説明はヘルプへ移し、操作中の画面に詰め込まない。
