# Tapli競合調査とMGXへの採用判断

調査日：2026年9月20日。TapliMIX v1.6.2.2、MGX `a44479e` を基準とする。今回の成果は調査と課題一覧。アプリ本体の機能変更・本番反映は行っていない。

**MGXが先に埋めるべき差は「定番MIXを正しい構成で遊べる」「登録前に試せる」「どの種目でも同じ説明と操作で学べる」の3点。** その後に友人との多種目・多人数対戦へ進む。Tapliの111種全部や複雑なシーズン制度を一度に追うと、現在の入力・表示・公開品質の課題を拡大する。

## Tapliの強いところとMGXの差

[TapliMIX](https://taplimix.app/)は対局・練習・イベントをまとめたサービス。[Tapli](https://official-tapli.lovable.app/)は同卓した人とのカード交換や非公開メモを扱う別サービス。この2つを混ぜて「TapliMIXにすべてある」とは扱わない。

| 領域 | Tapli側の観測 | MGXとの差・判断 |
|---|---|---|
| 遊び始めるまで | 未ログインでNLHのCPU対局を開始し、ショーダウンまで実操作できた | MGXのゲスト練習は手札指定3種。通常CPU対局へゲスト体験を広げたい |
| MIXの幅と選択 | 111種の一覧、16のプリセットカード、毎ハンド/周回/DCなどの入口 | MGXは37種、通常公開25・preview12。定番構成の整合とpreviewの仕上げを先にする |
| 練習の調節 | Non-Fold、COM高速、時間制限、全席自己操作などを設定できる | MGXは席設定や手札指定の部品はあるが、学習目的から一括設定する導線が不足 |
| ルールの確認 | 種目別説明に加え、カードを入力して役と分割比率を確認できる | MGXの統一学習カードは13種。全公開種への拡充と独立判定ツールが有効 |
| 対人・コミュニティ | 公開卓・Private Room・大会・シーズンへの入口。部屋詳細は公式説明根拠 | MGXの対人APIはBadugi・2人限定。ローカルCPU大会とオンライン大会は別物 |
| 対局以外の利用 | ゲーム札、Studも扱う時計、tp配分の試算 | MGXのルール/大会部品を再利用し、練習会や店舗で使える形にできる |
| 復習 | 再生・ブックマーク・共有・AIレビューを公式案内 | MGXにも再生・メモ・タグ・JSON・AIフィードバックがある。共有や局面への結び付けを拡充 |

根拠は [練習](https://taplimix.app/practice?gameId=nlh)、[種目](https://taplimix.app/games)、[プリセット](https://taplimix.app/presets)、[役判定](https://taplimix.app/tools/qualifier)、[ツール](https://taplimix.app/tools)、[シーズン](https://taplimix.app/season)。認証の先にある機能は動作未確認なので、機能の存在説明と実際の品質を分けて評価した。

## 最優先で直すべき整合性

1. **HORSE/8-Game/10-GameのOmaha枠**：`proPresets.js` は `B06=PLO8`、学習用プリセットは `B09=FLO8`。TapliのHORSEはFLO8。WSOPのHORSE構造もLimit。標準名で提供する構成を一元化し、独自のPL混成なら別名と説明にする。根拠：[G006](GAP-REGISTER.md#g006)、[Tapli HORSE](https://taplimix.app/presets/horse)、[WSOP構造表41ページ](https://wsop.gg-global-cdn.com/wsop/2f5f1259-f5b3-49dd-b2bd-77ad575327a8.pdf#page=41)。
2. **NL 2−7 Single Drawの不足**：MGX `S01` はカタログも基底エンジンも固定リミット。一方で10-Game説明はNL 2−7 SD。NLの額入力・合法レイズ・all-in再開権まで実装しないと同じゲームにならない。既存FL版を残すかも明示する。G007。
3. **Archieの成立条件差**：TapliはHighが99以上、MGXは任意のワンペア以上。実際にMGXの評価処理へ88と99を渡すと両方成立した。ハウスルールの違いを明示するか、狙うルールへ評価器と説明を合わせる。公開前に確認する。G086。
4. **FLHがpreviewのまま**：定番MIXを一巡する前提が未充足。既存の品質条件を通して公開し、未公開種目を除いた組合せを標準HORSEとして見せない。G008。
5. **説明・公開状態・プレイ内容の分散**：画面ごとの別定義を減らす。現在の新しい丸卓について、実機横向きとホーム画面起動は前回記録上の未確認項目。この競合調査を理由に合格扱いにはしない。G046/G084。

## 採用順の提案

優先順位は、①初回プレイや学習をどれだけ改善するか、②既存部品を使えるか、③根拠が実操作か説明のみか、④サーバー・運営・品質確認の負担、で判断した。利用者数や売上の推定は置いていない。以下の期間は約束ではなく、各まとまりの相対的な規模。

| 順序 | まとまり / 対応ID | 最初の成果物 | 先に取り込む理由 | 依存・規模 |
|---|---|---|---|---|
| 0 | 標準構成と品質 G006–009/G046/G084/G086 | 正しいHORSE/8/10、FL/NLの明示、公開条件の確認 | 間違ったルールを覚える問題は新機能より重大 | エンジン変更を含み中〜大。NL27は独立作業 |
| 1 | 登録前の体験 G001 | 公開種目を選び、短いCPU体験を開始 | 最初の離脱を減らせる仮説。学習ページから実対局へつながる | 認証と保存の分離・履歴引継ぎ。中 |
| 2 | 共通ルールと判定 G031–034/G078 | 25種のルールカードと自由入力判定 | 既存評価器を使えて、MIX固有の「何が勝ちか」を解消 | ルールデータ整備と検証。中 |
| 3 | 練習設定 G020–024 | 全席操作、CPU速度、Non-Fold、初期スタック固定 | 同じ状況を繰り返し学びやすい | 全席操作は大、速度は小。モード別成績を分離 |
| 4 | 共有と卓の統一 G005/G010/G015/G045/G048 | 招待QR、定番MIX、MIX共有、匿名ハンド共有、対人卓の統一 | 友人を誘い、同じ教材を使うまでを短くできる | 小〜中。入力・伏せ札の退行を防ぐ |
| 5 | リアル卓で役立つ道具 G039/G073–076/G083 | スリープ防止、ゲーム札→タイマー | 店舗/練習会で使う理由を作れる | ゲーム札は中、時計は復帰/実時間管理を確認 |
| 6 | 多種目・多人数の友人戦 G053/G054等 | Badugi以外の2人対戦→3〜6人対戦 | 競合との差が大きい本丸 | サーバー共通化、複数端末、切断テスト。特大 |
| 7 | 定期開催→シーズン G066–070等 | 小さな定期会と結果ページから開始 | 人が集まる時間を作ってから公開卓を育てる | 運営責任者・参加需要が前提 |

金額入力、ルール判定、初回体験、共有、練習設定はいずれもソルバー不要。多人数対戦もソルバー不要だが、サーバー側の改修を省けるわけではない。AIレビューや種目提案は説明付きの補助として実装できるが、正確なEV/GTO最適解と同等とは扱わない。

## すぐには取り込まないもの

- **111種すべての追随**：名称数の増加より定番の正確さを優先。特殊な評価軸、複数ボード、ジョーカー、Scarneyなどは専用のルール・UI・再生検証が増える。
- **独自ゲームビルダー**：任意ルールの組合せを許すには、不正な構成と破綻する精算を検出する基盤が要る。
- **複雑なtp制度・決勝選抜・常設公開卓**：参加者規模も運営継続性も未検証。MGXでは定期練習会を先に試す。
- **Respectや知り合いコレクション、Flip**：MIX学習への効果が低い、または別サービスの目的。現段階では見送り。
- **Swipe Raiseの丸写し**：ユーザーが求める数値入力と確定操作を保つ。配色やレイアウトの一部を参考にする場合も、現在の緑の卓・ドロー時の赤い縁という意味付けを崩さない。

## MGXで維持する強み

復習メモ・タグ、学習クイズと進捗、手札指定からの反復、exact replay、CPU大会の途中再開、接続不良時の復帰案内、公開前の品質ゲートは既存。Chinese Poker/OFCも今回のTapli111種一覧にはない。Tapliに似せるためにこれらを削らない。「競合に見えなかった」ことを競合での不存在の証明とはしない。

## 判断の限界

実操作はTapliのゲストNLH1ハンド完走、設定の一部変更、NLH/Badaceyの役判定、Pick’em候補生成。認証が必要な対人戦や保存・同期、全111種の精算、実機レイアウト、性能は未検証。ゲストNLHの履歴は完走後も0件だったため、保存条件や原因を確認せず「Tapliの履歴品質が優れている」とは評価していない。

調査時点の公開情報とローカル実装の比較であり、各機能が継続率や学習効果を高めることは仮説。実装後は「初回1ハンド完了率」「ルール誤答率」「入力取消/失敗」「練習の再利用」「招待から同卓までの完了率」で効果を確かめる。測定値がまだないため、改善率や事業成果の数値は付けていない。
