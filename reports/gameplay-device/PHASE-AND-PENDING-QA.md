# 丸テーブルのフェーズ色・不具合修正・追加実機QA（2026-09-20）

前回の丸テーブル変更ではドロー時の色分けが抜けていた。従来の「緑のフェルトを保ち、ドロー中は縁を赤にする」仕様へ戻した。交換ラベルと交換枚数の欄も赤系でそろえ、次のベットでは通常色へ戻る。席・カード・操作欄の位置はフェーズで変えない。利用者の「いい感じのレイアウト」という反応を記録し、丸テーブルの構造を維持した。

[全体一覧](STATUS.md)・[検査集計](phase-evidence.json)を更新。以下の実機操作はUSB接続したiPhone17,3（iOS 26.5.2 / Safari 26.5.2）の専用検査ページを使用。ゲームの操作はDOMからボタンを押している。指による全操作や全てのゲーム状態を保証する検査ではない。

## 修正内容

| 問題 | 対応 | 確認 |
| --- | --- | --- |
| ドロー中も通常の縁色になる | 丸テーブルの色分岐を復元。色と操作ボタンが同じ進行状態を参照 | 実機縦35種目、WebKitの代表4種目×縦横、PC Badugi/2−7 TD |
| ルームコードをコピーできなくても成功表示になる | Clipboard APIが失敗したら代替処理。成功を確認して表示し、失敗時は長押しコピーを案内 | コピー部品4件・Friend Match画面18件 |
| 友達対戦の入力・ボタンが小さい | ボタン44px以上、入力文字16px、左右セーフエリアを確保 | 実機計測：最小44px / 16px |
| 長く遊ぶと保存容量が不足する | 古い補助ログを半分ずつ整理して大会・同期キューを再試行。対局履歴、認証、成績はこの処理で削除しない | 実機3形式の保存・再開、容量不足からの回復と回復不能のブラウザ2ケース |
| 保存失敗でも保存済みとして扱う | 失敗時はnullを返し、進行が戻る可能性を画面通知。直前の有効な保存は保持 | 関連ユニット・画面29件 |
| ローカル検査プロキシで友達対戦が再接続を繰り返す | WebSocket認証サブプロトコルと切断コードを正しく転送 | 実機2人対戦・接続復帰。検査環境の問題として区別 |

容量不足は実機の履歴が約3.5MB、補助ログが約1MBに達した状態で検出した。修正前の[記録](artifacts/phase-storage-before-fix.json)には補助ログ、同期キュー、ハンド履歴へのQuotaExceededErrorが残る。修正後は補助ログ約119KB、対局履歴約3.59MBで、[大会3形式の再開](artifacts/phase-physical-features-verified.json)が成功した。今回の対策で履歴を無制限に保存できるわけではない。補助ログを整理しても保存できない場合は通知し、最新進行が保存済みとは扱わない。

## 実機で今回完了した範囲

| 対象 | 結果 | 範囲 |
| --- | --- | --- |
| 通常対局35種目・縦393×695 | 合格 | 各1ハンド、自然CPU進行、配置・カード見切れ・操作の当たり判定、色切替、履歴の再生必須情報、精算・退出 |
| NLH / 2−7 TD / 2−7 SD | 合格 | 席・カード寸法・ポット・操作欄を直接測定して一致 |
| 数字入力 | 合格 | 88→削除→80、確定前に持ち点を変更しない、取消、再入力・80確定。数字キー113×48px、全キーの当たり判定 |
| Multi-Game 3形式 | 合格 | 各形式1ハンド→中断・再読込→再開後1ハンド。解放実績だけ検査用設定、強制決着なし |
| Dealer’s Choice | 合格 | NLH→Badugi、各1ハンド、キュー消費、色と配置 |
| Chinese / OFC | 合格 | 各3ハンド、結果の固定得点表示、履歴からの完全再現 |
| 友達対戦・通信復帰 | 合格 | iPhoneと別Chromium参加者、手札非公開、WS再接続、WS失敗からREST継続、HTTP中断から復帰、対局終了と再読込復元 |

友達対戦は実際のローカルAPIと通信した。通信障害は物理ブラウザ内の通信処理で意図的に発生させたもので、Wi-Fiスイッチを操作した検査とは区別する。

物理端末の検査情報はReactの画面更新より遅れることがある。大会でDRAWという検査情報に対して画面が次のBETになっている例を捕捉した。75ms後に検査情報だけがBETに追い付き、画面の色が変わらないことを確認したケースを記録する。継続的な色不一致を許容する修正ではない。通常35種目のA5 SDも診断情報の参照を修正後に再プレイして合格。初期の失敗記録は削除せず保存している。

## ブラウザ・コード検査

- 最終WebKit：色8件、種目間配置3件、容量不足2件の13件合格。PC専用2件はモバイルプロファイルでは対象外として除外し、PC Chromiumで別途2件合格。
- 保存対策後のMulti-Game：3形式の操作・再開・結果確認が合格。ブラウザの最終順位は明示的な優勝状態を注入する検査で、自然決着は実機の各ハンドと区別する。
- Friend Match通信とPWAの画像・manifest再検査：2件合格。ホーム画面への追加成功を意味しない。
- 部品：フェーズ色・座席10件、コピー4件、Friend Match18件、保存・再開・通知29件合格。
- ビルド成功。変更箇所の静的検査はエラー0。App.jsxに既存の警告2件、ビルドに既存の大きい配信ファイルの警告が残る。

## 実機操作待ちの項目

- **最新丸テーブルの横画面**：WebKitでは確認済み。現時点の実機は393×695の縦。回転を依頼済みで、今回の実機横画面の合格とは記録していない。
- **ホーム画面追加・そこからの起動と再起動**：Safariの共有メニューから追加する操作を依頼済み。ページ操作ツールでは共有メニューを押せず、standalone起動はまだ観測していない。オフライン対局は実装対象外。
- 数字キーの物理タッチは先行版で利用者が80を確定した記録がある。今回の丸テーブル版での全ボタンの指操作・押しやすさの主観回答は別途となる。

実装はローカルの実機確認ページへ反映した。本番へは配信していない。
